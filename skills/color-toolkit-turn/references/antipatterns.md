# 反模式与常见错误

## AP-01: 仅依赖 HEX 而忽略其他色彩空间

**错误做法：**
只给用户 HEX 值，不做 RGB/HSL/CMYK 的完整转换。用户需要在其他工具中输入 RGB 值时无从参考。

**正确做法：**
使用 `convert_color()` 一次性输出 HEX / RGB / HSL / HSV / CMYK / 亮度 / 色温全维度数据，让用户在不同场景下都能直接使用。

**深层原因：**
不同设计工具和开发框架使用的色彩空间不同（CSS 用 HEX/HSL，打印用 CMYK，图像处理用 RGB），只给一种格式会强迫用户手动换算，降低效率。


## AP-02: 对比度只给数值不给结论

**错误做法：**
输出 `WCAG 3.3:1` 就让用户自己判断是否合规。用户不知道 3.3:1 对小文本是 FAIL、对大文本加粗才是 AA。

**正确做法：**
使用 `get_contrast()` 的 all 模式或 `find_accessible()`，输出时附带等级标签（AA/AAA/FAIL）和结论说明。例如：`WCAG 3.3:1（小文本 FAIL，大文本 AA）`。

**深层原因：**
WCAG 标准有字号和字重的组合判断逻辑（小文本 4.5:1，大文本 3:1），用户很难记住这些阈值。工具直接告知用户是否合规。


## AP-03: 直接在白色背景上用纯黄色做文字

**错误做法：**
在白色或浅色背景上使用 `#FFFF00` 作为文字颜色，不配合 text-shadow 或深色背景。

**正确做法：**
使用 `readability-set` 复合组件在深色背景上展示黄色文字效果；如需白底使用，先通过 text-shadow 或被选深黄（`#D4A017` / `#B8860B`）搭配 `find_accessible()` 验证。

**深层原因：**
黄色亮度 0.928（白色=1.0），在白底上对比度仅 1.07:1，远低于 WCAG 最低要求 3:1。肉眼几乎无法分辨，属于严重的无障碍违规。
