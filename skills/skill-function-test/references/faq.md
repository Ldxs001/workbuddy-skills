# FAQ

### 场景测试和功能测试有什么区别？

场景测试从 SKILL.md 解析触发场景 → 核心能力 → 工作流程，检测场景链路能否走通。功能测试（D1-D6）检测单个函数能否跑通、有没有数据污染等。场景测试是场景级的，功能测试是函数级的。

### 为什么有这么多 WARN？

D4（噪音）和 D6（边界）的 WARN 很多是设计选择而非 bug——CLI 脚本用 print 输出是故意的，某些函数缺少边界说明也是因为功能简单。LLM 后处理阶段会逐条判断这些 WARN 是误报还是真问题。

### 修复后功能会不会坏？

不会。阶段 6（回归循环）在每次修复后自动重测全量项目，并与修复前的基线对比确认无退化。阶段 7（回归确认）输出详细的对比表。

### 测试残留文件怎么清理？

阶段 9 自动删除 `.scenario-test_*` 临时文件，保留最终报告。备份目录保留最近 5 个。

### 误报怎么处理？

阶段 7.5（LLM 后处理）会把每条 WARN/BLOCK 的上下文（文件:行号 + 附近代码）展示给 LLM，由 LLM 判断是 FP 还是真问题。被标记 FP 的条目不参与修复。

→ 更多用法详见 `references/guide.md`
