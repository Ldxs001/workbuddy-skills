# 反模式（Anti-Patterns）

> 本文件收录 skill-scenario-test 使用过程中的常见反模式。

### 测试范围过大
选择全部维度却不设 fix_mode=0，可能导致大量 WARN 涌入，LLM 后处理阶段难以逐一审核。

**正确做法**：首次测试用 `fix_mode=0`（仅报告），选定核心维度后逐步扩大。

### 跳过备份直接修复
不备份就执行修复模式，一旦修复失误无法回滚。

**正确做法**：始终使用 `runner.py` 全流程，阶段 1 自动备份。

### 在目标技能目录下手动修改测试残留文件
`.scenario-test_*` 文件为自动生成，手动编辑会被覆盖。

**正确做法**：依赖阶段 9 清理，不手动修改。

### 修复建议越界
LLM 在阶段 5 修复时不应新增功能或修改业务逻辑。

**正确做法**：只修复阻断性 bug（F-0）和风险项（F-1），不扩展功能。
