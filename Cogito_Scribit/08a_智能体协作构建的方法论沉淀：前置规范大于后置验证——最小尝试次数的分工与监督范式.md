# 智能体协作构建的方法论沉淀：前置规范大于后置验证——最小尝试次数的分工与监督范式

> 先分工，后名分；先封堵，后验证；监督前移，试错留白。
> 更新：2026-08-02（08a 启动篇）。本篇属于 **08 系列**（智能体协作方法论沉淀容器：08 范式层 + 本篇操作层 + 未来同主题扩展）。

---

## 一、从"为什么"到"怎么做"：08 与 08a 的分层

第八篇回答了范式问题：**在确定的边界内让 LLM 填空，在确定的边界外由确定性系统决策。** 它证明了"LLM 只填空、不决策"是三个独立智能体不约而同的架构选择。

但范式只回答了"谁做决策"，没有回答下一个问题：**填空之后，如何让系统"第一次就做对"？**

| 维度 | 第八篇（范式层） | 本篇（操作层） |
|------|----------------|--------------|
| **回答的问题** | LLM 能做决策吗？ | 做对的概率结构如何构造？ |
| **核心结论** | 不让 LLM 决策，只让它填空 | 前置规范 + 分工 + 监督前移 |
| **观察对象** | 决策 vs 填空的边界 | 错误在时间轴上的生成与繁殖 |
| **方法** | 归纳（三智能体的共同选择） | 演绎（概率本性 → 结构手段） |
| **验证方式** | 三体印证 | 代码铁证（validate 的死亡） |

两个问题不同，答案也不同。第八篇的结论是"把 LLM 挤出决策位"；本篇的结论是"挤出去之后，把'必须一次做对'的环节也从 LLM 手里拿走"。

## 二、目标的重新定义：最小尝试次数

### 2.1 "做对"的定义修正

传统工程默认的"做对"是：**出错后能修回来**。于是体系围绕"验证 → 定位 → 修复 → 回归"设计，把大量资源投入到后验证层。

本篇修正这个定义：

> **做对 = 首次尝试即符合契约的概率足够高。**

| 维度 | 传统定义（后验证） | 修正定义（前置规范） |
|------|------------------|-------------------|
| **核心假设** | 出错是常态，修是常态 | 出错成本应被消灭在生成时刻 |
| **资源投向** | 验证器、检查器、复审流程 | 生成通道的约束、schema、映射表 |
| **成功标志** | 错误被检出并修复 | 错误根本没有生成通道 |
| **退化形态** | 验证层本身成为死代码 | 约束成为生成的一部分 |

### 2.2 最小尝试次数为什么与 LLM 本性相悖

LLM 是概率生成器。它的工作方式是**采样-猜测**：给定上下文，输出一个概率分布上的样本。把它放在"必须一次做对"的位置，等于把概率事件当确定性事件使用。

这不是模型大小或质量的问题，是机制问题。任何 LLM，无论多强，其单次输出的正确性都是概率事件；要求它"第一次就符合契约"，本质是要求概率为 1——这不存在。

于是有了三个看似合理、实则全部无效的补救：

| 补救手段 | 本质 | 为什么无效 |
|---------|------|-----------|
| **调低温度** | 收窄采样分布 | 只降低多样性，不提高契约符合率；0 温下仍可能输出非法格式 |
| **加强提示词** | 提高指令遵循概率 | 概率性约束，`0.99^10 ≈ 90.4%`，步骤越多越不可靠 |
| **多轮自我修正** | 试错循环 | 是"验证-修复"的变体，把后验证从外部搬进 LLM 内部，成本更高 |

这三者都是**试错循环的变体**。它们降低的是"失败后的修复成本"，而不是"首次失败的概率"。真正的解法不是让 LLM 更努力，而是**重新分工**。

### 2.3 解法：重新分工，而非让 LLM 更努力

填空域设计因此获得一个新判据——不再只问"LLM 能不能做"，要问：

> **这件事允不允许试错？**

| 判断 | 归属 | 理由 |
|------|------|------|
| **不允许试错**（契约严格、错误会繁殖） | 移出 LLM，交给确定性系统 | 首次失败概率 × 繁殖代价 = 不可接受 |
| **允许试错且试错成本低**（局部、可隔离） | 留给 LLM | LLM 在窄口径内的填空质量可预测（第八篇：500 字准确率 > 90%） |

这个判据把第八篇的"决策半径"概念向前推进了一步：不只压缩 LLM 的**决策**半径，还压缩它的**容错**半径——把"错不起"的环节从它手里拿走。

## 三、监督的时间非对称性（理论根基）

### 3.1 反直觉命题

有一种流行的错觉：系统越成熟，后期越不需要监督。本篇给出的命题相反：

> **监督不是"越到后期越不需要"，而是"越到后期越不可能逃避"。**

前半句是错觉的来源，后半句是严格含义。理解这个非对称性，是接受"前置规范"的前提。

### 3.2 错误的时间累积与自我繁殖

LLM 的错误不是孤立的，它**自我繁殖**。Structured Writer 的前文回顾机制是繁殖通道的典型：每一节写作都注入"已写内容回顾"，后续节基于前文继续生成。

```
节 1 生成（捏造了一个不存在的引用来源）
  ↓ 写入 context_buffer
节 2 生成（前文回顾包含节 1，基于错误继续）
  ↓ 引用该来源
节 3 生成（前文回顾包含节 1+2，错误链条加长）
  ↓ ...
节 N：错误已经在 N-1 处被"引用"过
```

| 错误被发现的时间 | 修复成本 | 影响范围 |
|----------------|---------|---------|
| 节 1 生成时 | 重写一节 | 1 处 |
| 全文生成后 | 重写全部引用链路 | N 处 + 参考文献节 |
| 交付后（用户发现） | 全文重写 + 信任损失 | 不可逆 |

**后期修正意味着全文重写。** 这不是修辞，是前文回顾机制决定的算术：错误进入 context_buffer 之后，后续所有节都基于它生成，单点修复无法抹去已经写入的引用链条。

### 3.3 监督点的分布决定一切

| 监督策略 | 监督点位置 | 监督粒度 | 逃避代价 |
|---------|-----------|---------|---------|
| **前置规范** | 生成时刻（错误尚未出生） | 每格校验 | 零——错误根本没有出生 |
| **后置验证** | 交付时刻（错误已繁殖完毕） | 一处校验 | 指数——检测全部累积错误 |

前置规范把监督放在**每格填空的出口**：输出格式 schema 校验、引用编号合法性校验、参数范围校验——每个出口一道闸。后验证把监督放在**整篇文档的末端**：一处检查，面对的是全部累积的错误。

**前期逃避监督的代价，在后期以指数形式返还。** 这是"监督越到后期越不可能逃避"的严格含义：你可以在前期省掉一次校验，但省不掉的是后期为这次省略支付的全文重写成本。监督没有消失，它只是从"每格的轻量校验"变成了"末端的沉重清算"。

## 四、前置规范：错误空间的前移封堵（结构化手段）

### 4.1 后验证的成本结构

后验证的成本不是常数，是四段式：

```
检测（发现异常）
  ↓ 概率衰减
定位（找到异常源头）
  ↓ 概率衰减
修复（修正源头）
  ↓ 概率衰减
回归（确认不再复发）
```

每一段都是概率衰减。错误越晚被发现，累计需要穿越的衰减段越多，修复成本指数上升。而后验证的终极形态，不是"更好的验证器"，而是**验证器的自我淘汰**。

### 4.2 代码铁证：validate 的死亡

Structured Writer 的 `citation_validator.py` 文件头注释（v1.1.0b14 之后）原文：

> 引用检查（validate）已于 1.1.0b14 移除——引用在生成时由后处理确定性完成，检查属过渡期补救，无调用点，为死代码。

这是一个完整的"后验证被前置规范淘汰"的生命周期：

| 阶段 | 状态 | 说明 |
|------|------|------|
| v1.1.0b14 前 | validate() 活跃 | 生成后检查引用合法性，是后验证 |
| v1.1.0b14 | validate() 移除 | 前置规范（生成时确定性后处理）已封死错误空间 |
| 之后 | 死代码残留 | 检查不再被调用，因为错误根本没有生成通道 |

**后验证不是被证明无用，而是被前置规范证明多余。** 一个还在依赖后验证的系统，说明它的前置规范还没封死。这可以作为架构审查的一条判据：你的系统里还有没有"验证器"？如果有，它验证的错误，为什么不能在生成时被禁止？

### 4.3 引用后处理：完整机制剖析（活例）

引用是"前置规范"最完整的实现。它的管线是：

```
LLM 写作约束：正文只允许输出「引用自来源N」/「引自来源N」标记
  （prompt 硬约束：不要直接使用编号格式）
  ↓
Python 归一化：连续列举「引用自来源1、来源2、来源4」→ 每个来源补上标记
  ↓
Python 扫描：提取全部真实引用 → 按首次出现顺序去重
  ↓
Python 建映射：旧编号 → 新编号（未用到的来源不参与编号）
  ↓
Python 替换：真实引用 → 新编号格式；不存在的来源 → 标记直接删除
  ↓
Python 建参考文献节：只用真实引用来源，悬空条目消失
  ↓
LLM 仅做格式美化：拿到「已编号的元信息 + desc」→ GB/T 7714 规范化
  （格式错误自动回退 Python 版本）
```

为什么说**假引用零生成通道**：

1. LLM 声称的"来源 N"，其合法性由 Python 的 `all_rag_headers`（真实 RAG 文档元数据）决定；
2. 不存在的 N，Python 直接删除标记（`return ""`），参考文献节里对应条目**根本不出现**；
3. 未使用的来源不参与编号——LLM 无法通过"列一堆来源"来虚增参考文献；
4. LLM 在最后一步只能**美化格式**，不能增删条目，且失败自动回退。

于是捏造参考文献从"写了假引用后被验证出来"，变成了**"假引用根本没有生成的通道"**。这就是前置规范与后验证的分野：后验证在错误发生后拦截，前置规范让错误无法发生。

## 五、分工先于名分：agent 定义之争的消解（组织手段）

### 5.1 名分之争是伪问题

"这算不算真正的 agent？""是 loop 还是 workflow？""是 ReAct 还是链驱动？"——这些是名分之争。

名分无法验证：没有一把尺子能量出"真正的 agent"的标准。而分工可以验证：每一层只做一件事、输入输出 schema 可记录、责任可追溯到具体角色。

> **分工比是否真正"agent 定义"有用得多，也重要得多——因为分工是可监督的，名分不是。**

### 5.2 分工三问

设计任何 LLM 系统时，只需要回答三个问题：

| 问题 | 回答落点 | 监督方式 |
|------|---------|---------|
| **谁决定边界？**（做什么、顺序、范围） | 人类 / 确定性系统 | 链定义、模板、大纲——生成前可审查 |
| **谁负责填空？**（生成内容） | LLM | 每格输出的 schema 校验 |
| **谁承担监督？**（验证契约符合） | 前置规范：生成通道本身 | 错误无生成通道 = 监督在出生点完成 |

三个问题落到具体角色，系统结构就清楚了；答不出来，说明分工还没设计完。名分之争在分工三问面前自然消解——你不需要定义"这是不是 agent"，你只需要说清楚三问的答案。

### 5.3 三个"伪 agent"都做得对

回望第八篇的三个智能体——它们都不是"真正的 agent"（不是自主决策的实体），但都交付了高质量工作：

| 智能体 | 谁定边界 | 谁填空 | 谁监督 | "agent 名分" |
|--------|---------|--------|--------|------------|
| **Orchestrator** | 编排器/用户定链 | LLM 填步骤输出 | 链定义 + 每步输出校验 | 伪 agent |
| **RAG Assistant** | 算法定穷举策略 | LLM 标 entities/attrs/rel | 输出格式状态机 + 参数校验 | 伪 agent |
| **Structured Writer** | 模板 + 大纲规划器 | LLM 填子结构正文 | 引用后处理 + 模板 desc 注入 | 伪 agent |

**做得对，恰恰因为它不追求"真正的 agent"。** 三个系统的成功来自分工结构的清晰，而不是智能体身份的纯粹。这验证了 5.1 的命题：决定成败的是分工，不是名分。

## 六、三体回望：操作层在三智能体的印证（衔接 08）

### 6.1 操作层四手段 × 三智能体

| 手段 | Orchestrator | RAG Assistant | Structured Writer |
|------|-------------|---------------|-------------------|
| **前置规范** | 链在执行前静态确定 | 穷举策略算法预展开 | 引用后处理 + 模板 desc 权威注入 |
| **最小尝试次数** | 每步 1 次调用，无 ReAct 循环 | 检索切片确定性执行 | 每节独立生成，无全文重写 |
| **分工结构** | 编排器决定/LLM 执行 | 智能体定"查什么"/技能层定"怎么查" | 模板定骨架/LLM 填血肉/引擎执行 |
| **监督前移** | 缺参数不执行（第 7 条） | 三层次硬约束（格式→参数→重试） | validate() 被淘汰 = 监督在生成点完成 |

### 6.2 与第八篇命题 A-D 的对应

| 第八篇命题 | 本篇的推进 |
|-----------|-----------|
| **A：决策半径与可靠性负相关** | 压缩的不只是决策半径，还有容错半径——"错不起"的环节移出 LLM |
| **B：确定性锚点是杠杆** | 锚点不只是限制/杠杆，它是监督的载体——监督点内嵌于锚点本身 |
| **C：三填空域不重叠** | 不重叠的原因：三问分工不同，边界由角色划分，非由内容划分 |
| **D：回到当下** | 最小尝试次数 = "回到当下"的严格化：以 LLM 的概率本性为设计前提 |

第八篇证明了"LLM 只填空"；本篇证明"填空之后的每个出口都有一道闸"。两篇合起来才是完整的架构判断：**LLM 不决策、不错得起、不被后验证。**

---

## 七、一句话总结

> **先分工，后名分；先封堵，后验证；监督前移，试错留白。** LLM 只填空、不决策、不碰"必须一次做对"的环节——前置规范把监督放到错误出生的时刻，分工把责任划到具体角色，而"agent"这个词，从设计判断中彻底消失了。
