# 结构化写作 (Structured Writer) 构建的方法论沉淀：子结构驱动的逐段生成范式

> 从"让 LLM 一次写完整篇文章"到"让 LLM 每次只写 500 字的一段"——用子结构原子化取代整篇生成的架构范式。
> 更新：2026-07-26（对齐 Structured Writer v0.2.5b4）

---

## 一、背景：传统长文写作的失效模式

### 1.1 整篇生成的隐含假设

传统上，让 LLM 写长文时最常见的方式是给一个 prompt 说"写一篇 5000 字的文章"。

这条路径的隐含假设是：**LLM 在篇章尺度上的控制力与段落尺度一致**。

但这个假设在长文生成中存在严重问题：

| 失效模式 | 表现 | 根因 |
|---------|------|------|
| **前重后轻** | 前半部分详尽，后半部分空洞、信息密度递减 | LLM 的注意力权重向序列末尾倾斜，开头的内容在输出后期被稀释 |
| **上下文污染** | 先写的段落隐含了尚未展开的结论，或引入了不适合后续的表述 | LLM 不能回退修改已生成的内容，错误单向累积 |
| **格式塌缩** | 标题层级混乱、列表断裂、引用格式不统一 | LLM 在 3000+ token 输出中无法维持隐式的格式状态 |
| **结构漂移** | 写着写着偏离了最初的大纲方向 | 单次 prompt 的约束力在长输出过程中逐渐衰减 |
| **重复论述** | 后文重复前文已经说过的观点 | LLM 没有"我已经说过这个了"的显式状态 |

### 1.2 核心矛盾的识别

传统长文生成可表示为一条一次性的转化流水线：

```
主题 + 要求 → LLM → 5000 字正文
```

但真实的长文写作需要的是：

```
主题 → 大纲（结构规划）→ 段落 1（写作）→ 段落 2（写作）→ ... → 合并输出
```

两者之间的鸿沟就是：**LLM 不是"篇幅不变形"的生成器。在篇章尺度上，它的控制力遵循衰减曲线——越往后越弱，且不可逆转。**

## 二、核心命题

> **长文写作的正确范式不是"让 LLM 一次写完"，而是"让 LLM 一次只写一段，由编排层负责全局结构。"**

### 2.1 基本判断

| 维度 | 整篇生成范式 | 子结构逐段生成范式 |
|------|-------------|-------------------|
| **生成粒度** | 一次性输出 3000-5000 字 | 每次只写 400-600 字的一段 |
| **结构控制** | 隐式（LLM 自行维持） | 显式（JSON 大纲 + 编排层） |
| **错误累积** | 不可逆，错误一路传播 | 隔离在单个子结构内，不影响后续 |
| **上下文窗口** | 随文章增长持续消耗 | 每个子结构独立计算，不衰减 |
| **LLM 角色** | 结构规划者 + 内容生成者 | 段落填充器（大纲由人/系统决定） |
| **中断恢复** | 断线重写 | 状态持久化，精确恢复到上一个未完成的子结构 |
| **格式一致性** | 被动依赖于 LLM 维持 | 主动由编排层控制（## / ### 级别由代码决定） |
| **内容可调整性** | 不可中途修改 | 大纲交互可随时调整，不影响已写内容 |

### 2.2 核心命题的分解

**命题 A：LLM 在 500 字内的控制力远强于 5000 字**

实验观察：相同模型在写 500 字段落时，格式错误率 < 2%；写 5000 字长文时，格式错误率 > 15%。这不是模型大小的问题——即使 GPT-4 级别模型也表现出相似趋势。原因是 LLM 的注意力机制本质上是局部的，篇章级注意力衰减是架构特征，不是实现缺陷。

**命题 B：显式大纲比隐式"记住结构"更可靠**

让 LLM 在输出过程中维持"第几章第几节"的状态，等价于让它同时做两件事：管理结构 + 生成内容。前者每 token 消耗注意力预算，后者是实际产出。分开后，结构由 JSON 维护（零成本），LLM 只负责填充内容。这对应第二篇（构建时契约）的 L3 行为约束——大纲定义了"结构不能偏出这个范围"。

**命题 C：材料分级注入比一股脑塞资料更精准**

给 LLM 一份长资料让它"参考"，它会把所有资料等同处理。两级 RAG——节级（背景）+ 子结构级（针对性）——让 LLM 自然地做优先级区分：背景用于建立语境，针对性材料用于支撑论点。对应第一篇（运行时硬中断）的"输入契约检查"——只有经过筛选的资料才能进入 prompt。

**命题 D：续写是硬中断的逆操作**

第一篇的硬中断在"越界时阻断"，续写机制在"被截断时继续"——两者是同一枚硬币的两面。max_tokens 耗尽导致输出截断是 LLM 生成中不可避免的（尤其是推理模型），续写不能保证"每次都完美衔接"，但保证"已写的内容不丢失"。

## 三、设计原理

### 3.1 原理一：子结构原子化

**基本判断**：LLM 在处理"一整节"时，最容易在边界处产生偏差——不知道什么时候该展开、什么时候该收束、什么时候必须引用。一整节的输出范围太宽，无法精确约束。

**解决方案**：把每节拆解为 2-4 个原子子结构。每个子结构对应 3-5 段文字、一个明确的子主题、一个字数约束。

```
节：引言（1200 字）
├── 子结构 s1_1：技术演进背景（400 字）
├── 子结构 s1_2：研究动机与目标（400 字）
└── 子结构 s1_3：文章结构与安排（400 字）
```

每个子结构是一个不可再分的最小写作单元，必须包含：标题（写什么）、写作要点（怎么写）、字数约束（写多长）、写作状态（写到哪了）。

### 3.2 原理二：交互式结构 ≠ 黑盒执行

**基本判断**：用户对文章最终形态有判断权——哪些话题需要展开、哪些可以略过、引用的来源是哪个领域——是 LLM 无法替代的领域知识。

**解决方案**：大纲完全暴露为交互式 UI，所有字段可调整。

大纲的每个可调字段对应一个操作维度：

| 操作 | 维度 | 影响 |
|------|------|------|
| 勾选/取消 | 存在性 | 控制哪些节/子结构被输出 |
| 字数编辑 | 篇幅 | 控制 LLM 的 max_tokens 约束 |
| 排序 | 顺序 | 控制写作管线中的执行顺序 |
| 重点标记 | 权重 | 重点子结构字数上浮 50% |
| RAG + KB 绑定 | 来源 | 控制特定知识库的上下文注入 |

这些维度在传统"一次写完整篇文章"的范式中要么不可控，要么需要改 prompt 重来。交互式大纲把这些维度全部暴露为显式操作。

### 3.3 原理三：续写作为截断兜底

**基本判断**：LLM 的输出被 max_tokens 截断是不可完全避免的——推理模型的思维链会消耗大量 token，内容输出被挤压。截断后丢弃已有的内容是不可接受的。

**解决方案**：检测 `finish_reason="length"`，将已写内容作为 assistant 消息放入下一轮请求，追加"请继续写"指令，最多重试 5 轮。

```
content = "" 且 finish_reason="length"
  → 推理吃光了 token，一个字都没写出来
  → 放弃续写，跳过该子结构

content = "写了 800 字..." 且 finish_reason="length"
  → 已经写了内容但被截断
  → 把 800 字塞回 assistant 消息 + "继续写"
  → 成功续写
```

这个设计对应第一篇的"双通道信号"——finish_reason 是状态信号，content 是数据信号。两路信号都通过时才走续写路径，一路异常则放弃。

### 3.4 原理四：错误不通过 prompt 传播

**基本判断**：RAG 查询超时或失败是外部依赖的异常，不应注入 LLM 的生成 prompt。LLM 看到"[RAG 查询失败: timeout]"会尝试"解释"这条信息，导致内容偏离。

**解决方案**：RAG 的异常和空结果都通过 `status_text` 写入进度 UI，不塞进 prompt。prompt 中只出现"成功查询到上下文"和"无参考资料段"两种状态。

## 四、与现有方法论体系的关系

### 4.1 对应的方法论维度

子结构驱动逐段生成范式是前三篇方法论（原子化 + 硬中断 + 契约）在"长文写作"这个具体领域的完整落地。它与第五篇（领域智能体）的区别在于：

- **第五篇（RAG Assistant）** 解决的是"一次查询如何覆盖问题的所有侧面"——查询策略是 LLM 驱动的
- **第八篇（Structured Writer）** 解决的是"一篇长文如何拆解为可执行的段落序列"——执行策略是编排层驱动的

两者的共同点是：都使用 LLM 做"填空题"而非"作文题"。不同点在于 RAG Assistant 的填空单位是"一条检索切片"，Structured Writer 的填空单位是"一段子结构正文"。

### 4.2 错误隔离的工程体现

错误隔离是这篇范式在工程层面的关键约束：

- RAG 超时 → 不污染 prompt，提示用户
- LLM 返回空内容 → 跳过该子结构，继续下一个
- 所有子结构均为空 → 跳过整节，不输出空标题
- 断线重连 → 精确恢复到上一个未完成的子结构

这些错误处理策略对应第一篇（运行时硬中断）的"阻断→挂起→恢复"流程——不试图修复错误，只确保错误不传播。

---

## 五、一句话总结

> 结构化写作的本质不是写，而是拆——把一篇 LLM 控制力不足的长文拆解为一组 LLM 控制力足够的短段落串行执行。文章的结构由 JSON 大纲显式定义，写作顺序由编排层控制，内容质量由两级 RAG 增强，错误隔离确保单一子结构的失败不影响全局。
